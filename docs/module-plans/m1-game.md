# M1 执行计划：游戏逻辑

本计划面向游戏逻辑负责人，目标是提供可脱离页面、三维库和灵矽运行的规则模块。状态为待评审、未实施；业务规则引用[实现方案第 2 节](../implementation-plan.md)，验收记录见[统一要求](README.md)。

## 1. 范围、输入与交付

- 负责 `web/src/game/` 及其规则测试和模块说明。
- 输入：M0 共享契约、本局编号和时间、正数苹果寿命、动作请求、统一坐标与移动参数；测试可以注入固定时间与随机序列。
- 输出：游戏快照、有序游戏事件、实际动作结果。
- 负责苹果与分数的唯一写入，不等待渲染回调，不调用灵矽或麦克风。

独立规则开发不依赖账号和牛模型；方向、抓取和疲惫的待评审选择确认后才固定相应行为。

## 2. 执行步骤与阶段产物

| 阶段 | 工作 | 交付物 | 验证项 |
| --- | --- | --- | --- |
| M1-1：状态与时间 | 实现准备、进行、结束和绝对截止时间；校验配置 | 可控时间驱动的本局状态 | 60 秒边界、非法配置、重复结束 |
| M1-2：苹果生命周期 | 实现两个独立槽、到期、抓取后补位及随机位置 | 苹果状态与唯一事件 | 数量上限、准确补位、不重复处理 |
| M1-3：移动与抓取 | 实现步进、转圈、边界、路径碰撞和计分 | 实际位置与抓取结果 | 经过苹果不漏抓，同一苹果不重复加分 |
| M1-4：动作与疲惫 | 实现有界队列、优先停止、去重、取消和疲惫状态 | 可完成与取消的动作请求 | 旧请求、超时、停止及疲惫不暂停规则 |
| M1-5：交接 | 接受 M0 装配，向 M2/M3 提供固定演练结果 | 模块说明与测试输出 | 表现层不反向决定规则 |

## 3. 必验标准

规则测试使用精确时间注入，不用真实等待代替边界检查。下表中 `t` 表示苹果抓取或到期的逻辑时刻，单位为毫秒。

| 编号 | 给定条件与操作 | 预期结果 | 验证方式 |
| --- | --- | --- | --- |
| M1-A01 | 使用默认配置开始本局 | 初始分数为 0，同时恰有 2 个可抓取苹果，各自到期时间为出现后 3000 毫秒 | 状态断言 |
| M1-A02 | 对空值、非数字、无穷值、0 和负寿命尝试开始，再使用正数 | 非法配置不创建运行中的局；合法寿命用于本局，运行中不能热改 | 参数化检查 |
| M1-A03 | `t` 抓取一颗苹果，更新至 `t+999` 和 `t+1000` | 先无补位，后恰好补一颗；分数仅加 1 | 可控时间与事件断言 |
| M1-A04 | 一颗苹果到期，更新至到期后 999 和 1000 毫秒 | 分数不变、本局继续；到 1000 毫秒才补一颗 | 可控时间与事件断言 |
| M1-A05 | 同时抓到或到期两颗，推进补位时间 | 两个槽独立补位，场内始终不超过 2 颗，不只补一颗或多补 | 状态序列断言 |
| M1-A06 | 先抓取，再推进到该苹果原到期时刻；重复提交碰撞 | 已抓苹果不再到期、不重复计分或安排第二次补位 | 事件编号与数量断言 |
| M1-A07 | 同一苹果在到期时刻与角色接触 | 按约定到期优先，不加分；仅产生一次移除和补位安排 | 精确边界检查 |
| M1-A08 | 在第 59999 毫秒和第 60000 毫秒处理有效碰撞及补位 | 截止前可抓取；截止时先结算，分数固定，不再生成苹果 | 精确边界检查 |
| M1-A09 | 一次更新跨越较长间隔或后台停顿 | 按实际截止时间推进；没有补记抓取、批量补出错过苹果或延长本局 | 跳时检查 |
| M1-A10 | 移动路径穿过苹果但终点不在碰撞范围内；再撞场地边界 | 路径上的有效苹果被抓取；角色位置仍在场地内，结果说明触边 | 路径碰撞与边界检查 |
| M1-A11 | 填满约定队列，再请求动作，随后发停止 | 满队列拒绝新请求；停止优先取消执行和等待项，各请求只结束一次 | 动作结果序列 |
| M1-A12 | 重复请求编号，旧连接或旧局请求迟到 | 不重复位移或计分；旧局请求不能改变当前局 | 去重与隔离检查 |
| M1-A13 | 按最终批准的疲惫规则完成动作并继续移动和推进时间 | 疲惫计数与恢复准确；苹果和本局时钟不暂停，取消动作不计完整运动 | 可控时间与状态检查 |
| M1-A14 | 重复结束本局，完成动画样例后再来一局 | 结束事件和动作响应不重复；新局编号、分数、槽和请求记录重新初始化 | 生命周期检查 |

补位位置使用固定随机序列验证：位于可见可达范围，不与现有苹果或牛当前抓取区域重叠；有限随机尝试后仍可从有效候选点生成，测试不能陷入无限循环。

## 4. 联调与完成条件

与 M2 确认快照位置和抓取事件可直接驱动表现，与 M3 确认计时计分展示，与 M5 确认工具返回与实际结果一致。提交规则测试输出、关键事件样例和运行说明；全部必验项通过后由 M0 复核。

参数或产品规则未确定时标记相关项阻塞；不会为了先通过测试自行引入生命值、过期失败、暂停或自动寻路。
