# M2 执行计划：三维角色与场景

本计划面向角色与场景负责人，目标是把共享游戏状态表现为可交互的牛七七，并实际产出可编辑的三维源文件、运行时模型和动作片段。状态为待评审、未实施；视觉方向以[实现方案](../implementation-plan.md)中的待评审选择为准，验收记录见[统一要求](README.md)。

## 1. 范围、依赖与交付

- 负责 `web/src/scene/`、`web/public/assets/niu七七/`（实际目录名由 M0 统一确定）、角色和场景资源及本模块演示与说明。角色资源、界面资源和音频资源分别归 M2、M3、M4，实际目录在 M0 初始契约中登记。
- 输入：M0 的场景坐标、游戏快照、唯一编号的事件、渲染尺寸，M4 的播放音量。
- 输出：三维画面、角色动作、苹果入袋表现、尺寸调整与资源释放结果。
- M1 是真实位置、苹果和得分的来源；可先用固定快照独立开发。角色方向和造型先获得评审，再继续细化动画。

当前项目没有可直接使用的三维模型、骨骼、贴图或动作文件。M2 需要从零制作或程序化生成占位素材，并提交可编辑源文件、导出的 GLB、资源清单和预览证据；不能把 Three.js 几何占位体或截图当作最终三维素材交付。

## 2. 执行步骤与阶段产物

| 阶段 | 工作 | 交付物 | 验证项 |
| --- | --- | --- | --- |
| M2-1：概念与资产规格 | 确认牛的比例、颜色、眼罩、口袋、苹果、场地风格和镜头；登记面数、材质、贴图、骨骼和动画命名约束 | 概念图/模型草图、资产清单、规格记录 | 用户确认视觉方向；M0 确认坐标和命名契约 |
| M2-2：基础模型与材质 | 制作牛、眼罩、口袋、苹果、地面和边界；建立材质与贴图；保留可编辑源文件 | `niu七七.blend`（或等效源文件）、`niu七七.glb`、`apple.glb`、贴图和预览图 | 模型可打开、材质不丢失、节点和口袋挂点存在 |
| M2-3：骨骼与绑定 | 为身体、手臂、腿、尾巴、头、眼罩和口袋挂点建立骨骼；绑定网格并检查权重 | 骨架图、节点清单、绑定源文件和导出模型 | 动作时无明显塌陷、穿插；口袋挂点可独立控制 |
| M2-4：动作片段制作 | 制作 `idle`、`turn_left`、`turn_right`、`turn_back`、`walk`、`face_front`、`spin`、`somersault`、`reach`、`grab`、`pocket`、`tired`、`recover`、`talk`、`blink`、`stop`；标记循环、时长、可打断点 | 动作清单、动作预览、带动画的 FBX/GLB 和源文件 | 每个片段可独立播放；循环首尾连续；动作可按规则打断 |
| M2-5：Three.js 播放器 | 使用动画混合器加载 FBX/GLB，建立转向/行走/回正/技能/抓取/疲惫/说话状态映射和事件去重 | 场景播放器与固定事件演示 | 逻辑位置由 M1 驱动；动画不改分数、苹果生命周期或时间 |
| M2-6：整合与调优 | 接 M1/M3/M4，检查真机渲染、尺寸、动作组合和资源释放 | 资源版本、性能记录和交接说明 | 完整三分钟无渲染故障，资源不随局数持续增长 |

## 3. 动作资产规格

以下是首版建议目标，不是已经生成的素材。实际时长可在第一轮预览后微调，但片段名称、循环属性和打断边界要在 M0 共享契约中固定。

| 片段 | 循环 | 建议时长 | 默认优先级 | 可被打断 | 用途 |
| --- | --- | ---: | ---: | --- | --- |
| `idle` | 是 | 2～4 秒 | 0 | 是 | 呼吸、轻微摇摆、随机眨眼 |
| `walk` | 是 | 每步 0.6～0.8 秒 | 1 | 是 | 移动期间循环，位置由 M1 推进 |
| `turn_left` / `turn_right` | 否 | 0.3 秒 | 2 | 停止可打断 | 原地转向 90 度 |
| `turn_back` | 否 | 0.6 秒 | 2 | 停止可打断 | 原地转向 180 度 |
| `face_front` | 否 | 0.3～0.6 秒 | 2 | 停止可打断 | 动作结束时回到固定前方 |
| `spin` | 否 | 1.2～1.6 秒 | 2 | 停止可打断 | 原地转一圈，不产生平移 |
| `somersault` | 否 | 1.6～2.2 秒 | 3 | 不建议中段打断 | 原地翻跟头，落地后站直 |
| `reach` | 否 | 0.6～0.9 秒 | 2 | 停止可打断 | 向苹果方向摸索 |
| `grab` | 否 | 0.4～0.7 秒 | 3 | 不建议中段打断 | 碰撞成立后的抓取动作 |
| `pocket` | 否 | 0.5～0.8 秒 | 3 | 不建议中段打断 | 苹果飞入口袋和收纳 |
| `tired` | 是 | 1.4～2.0 秒 | 2 | 是 | 扶腿喘气；可与低幅移动表现叠加 |
| `recover` | 否 | 0.8～1.2 秒 | 2 | 停止可打断 | 从疲惫回到站立 |
| `talk` | 是 | 0.4～0.8 秒 | 1 | 是 | 播报期间点头和嘴部开合 |
| `blink` | 否 | 0.1～0.2 秒 | 4 | 否 | 眼部叠加层，不替换身体动作 |
| `stop` | 否 | 0.15～0.3 秒 | 4 | 否 | 停止后的收尾姿态 |

动作优先级只用于表现层冲突解决，不能改变 M1 的请求顺序或得分。`grab` 和 `pocket` 的逻辑触发点是 M1 已经判定成功之后；苹果入袋动画延迟不影响得分和补位计时。`tired` 只是表现状态，是否进入疲惫以及何时恢复由 M1 产生事件。

## 4. 资源清单和制作工具

建议使用 Blender（开源三维建模与动画工具）制作和绑定模型，使用其 GLB 导出器生成浏览器资源；Three.js 只负责加载和播放，不作为建模源文件。若改用其他工具，必须能导出同等骨骼、材质和动画信息。

首版资产至少包括：

| 资产 | 运行时格式 | 必要内容 |
| --- | --- | --- |
| 牛七七 | GLB | 网格、材质、骨骼、11 个动作片段、口袋挂点、眼罩节点 |
| 苹果 | GLB 或共享低模 | 苹果网格、材质、旋转/缩放原点 |
| 场地 | GLB 或程序化平面 | 地面、边界参考点和固定镜头适配信息 |
| 本地预览 | PNG（Portable Network Graphics，便携式网络图形）或 MP4（MPEG-4 视频格式） | 正面、侧面、动作组合和手机尺寸预览 |

`manifest.json` 至少登记资产版本、源文件相对路径、运行时文件相对路径、文件大小、骨骼节点名、动作名、循环属性和导出工具版本。所有资源使用相对路径；换一台机器或从新工作目录加载不能依赖个人绝对路径。

## 5. 必验标准

| 编号 | 给定条件与操作 | 预期结果 | 验证方式 |
| --- | --- | --- | --- |
| M2-A01 | 打开资产源文件和运行时 GLB，检查牛、眼罩、口袋、苹果及场地 | 源文件可编辑；GLB 可加载；材质、贴图、比例和口袋挂点完整，不依赖本机绝对路径 | 源文件打开、GLB 加载、资源清单和预览图 |
| M2-A02 | 检查导出模型的节点名称与骨骼层级 | 头、躯干、四肢、尾巴、眼罩、口袋挂点名称符合契约；Three.js 能按名称取得节点 | 节点清单脚本与加载日志 |
| M2-A03 | 单独播放动作片段并记录循环和时长 | `idle`、转向、`walk`、`face_front`、`spin`、`somersault`、`reach`、`grab`、`pocket`、`tired`、`recover`、`talk`、`blink`、`stop` 均存在；循环片段首尾连续；非循环片段有结束事件 | 动作预览视频、动画名称和时长清单 |
| M2-A04 | 在走路、转圈、抓取、疲惫和说话之间按状态机切换 | 过渡不锁死；手、腿、口袋和眼罩不明显穿插；疲惫可与移动表现叠加 | 状态切换录屏与问题清单 |
| M2-A05 | 输入共享坐标中的四个方向位置与场地边界 | 屏幕方向符合约定，边界内角色和苹果可见，不自行翻转方向 | 固定坐标对照图 |
| M2-A06 | 移动、转圈和疲惫状态连续切换，并持续推进逻辑位置 | 表现跟随快照，疲惫不阻止真实移动；无遗留姿态锁住角色 | 组合动作录屏与位置对照 |
| M2-A07 | 收到含苹果来源位置的抓取事件，随后快照已移除该苹果 | 仍从正确位置播放入袋；只保留一次表现，动画不影响已经确定的分数 | 事件回放及只读检查 |
| M2-A08 | 苹果过期、相同位置新苹果出现；旧动画仍在播放 | 旧表现与新苹果按编号区分，不删除或移动新苹果 | 编号交错事件回放 |
| M2-A09 | 重复传入同一事件编号，再切换到新局 | 同一局事件不反复触发；新局不残留上局苹果、汗滴或入袋效果 | 重复与跨局回放 |
| M2-A10 | 输入静音、不同播放音量和停止事件 | 嘴部随实际播放变化；静音和停止后恢复，不凭聊天文字持续张嘴 | 音量样例录屏 |
| M2-A11 | 在 320、390、430 和 768 像素宽度调整容器，并显示底部输入区 | 场景按实际容器适配，角色、场地和苹果主要区域不被裁切 | 各尺寸截图，与 M3 联验 |
| M2-A12 | 连续运行三局，每局完整三分钟，再销毁场景 | 无未处理渲染错误；动画停止，资源监听和临时对象释放，资源数不随局数单调增长 | 运行记录与资源计数 |
| M2-A13 | 在目标 iPhone 上运行完整场景并抓取、转圈、疲惫 | 无画面丢失、持续卡死或影响控制的异常；记录实际帧间隔与设备 | 真机录屏和性能记录 |

M2-A11 建议性能目标为：目标 iPhone 前台完整运行 180 秒，平均帧率不少于 30 帧/秒，至少 95% 的帧间隔不超过 50 毫秒。此为待评审验收目标，不是已取得的测试成绩；目标机与预算确认后再执行，缺真机时不填写性能通过。不得为达到帧率删除本局必需动作或隐藏苹果。

## 6. 联调、交付与阻塞

交付角色与场景代码、可编辑源文件、运行时 GLB、贴图/材质、骨骼节点清单、动作片段清单、动作预览、资源版本和大小、事件样例、资源释放说明及验收证据。与 M1 联验路径与抓取，与 M3 联验场景容器，与 M4 联验音量驱动，与 M6 联验实际设备。

最低素材目录约定如下，由 M0 在首个契约版本中固定实际命名：

```text
web/public/assets/niu七七/
  source/                  可编辑源文件（如 .blend）
  models/                  运行时模型（如 niu七七.glb、apple.glb）
  textures/                贴图及材质资源
  previews/                正面、侧面、动作预览
  manifest.json            模型、节点、动作、版本和尺寸清单
```

如果采用程序化模型替代建模源文件，也必须交付可重复运行的生成脚本、固定版本的参数和生成后的 GLB；临时在代码里拼出的几何体只能用于占位，不能跳过动作和资源验收。

不在渲染回调中加分、补苹果或结束游戏。产品造型尚未批准时可以提交样例和反馈，不继续把未批准视觉当作最终交付。
