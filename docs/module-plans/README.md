# 模块执行计划与验收入口

本文用于分派牛七七项目的开发与验收工作。以下均为**待评审执行计划**，不是已经实现或测试通过的报告；编写计划不表示启动功能开发。

业务规则以[实现方案](../implementation-plan.md)为准，模块归属与人员安排以[并行协作方案](../parallel-development.md)为准。执行计划细化步骤与可验证标准，不修改固定一分钟、苹果数量、寿命、补位及计分规则。

## 1. 计划书清单

| 模块 | 执行计划 | 主要交付 | 最终验收负责人 |
| --- | --- | --- | --- |
| M0 | [共享契约与应用集成](m0-integration.md) | 公共契约、项目基础、装配入口、整体验证记录 | 用户与各模块负责人 |
| M1 | [游戏逻辑](m1-game.md) | 独立游戏规则、动作执行与确定性测试 | M0，视觉关联项与 M2 联验 |
| M2 | [三维角色与场景](m2-scene.md) | 可编辑三维源文件、GLB 运行时模型、骨骼和动作片段 | M0，角色视觉与动作由用户评审 |
| M3 | [页面与交互](m3-ui.md) | 三个页面状态、控制、聊天与移动布局 | M0，与 M4/M5 联验输入链路 |
| M4 | [浏览器音频](m4-audio.md) | 采音、音频帧、播放与打断 | M0，与 M5/M6 联验真实设备 |
| M5 | [灵矽接入与会话](m5-linx.md) | 绑定、连接、工具适配、文字语音和音频解码 | M0，与 M1/M4 联验真实链路 |
| M6 | [iOS 外壳](m6-ios.md) | 网页容器、权限、原生音频与生命周期适配 | M0，用户评审真机结果 |

M0 是必须落实的集成职责，可由其他模块负责人兼任。每个模块开始时登记实际负责人、工作分支和负责目录；目前不虚构人员姓名或排期日期。

## 2. 并行顺序与前置条件

1. **M0 第一阶段**：确认待评审产品选择，建立最小共享契约、固定样例与项目基础；M5 同时核对账号、权限和接入证据。
2. **模块并行**：M1 通过可控时间实现规则；M2/M3 使用固定样例；M4 使用录音与音频样本；M5 使用最小工具执行器；M6 先验证外壳能力。
3. **局部联调**：M1＋M2＋M3 完成本地游戏，M4＋M5 完成真实语音和工具链路。
4. **完整联调**：M0 装配，M6 接入同一页面，在目标 iPhone 完成真实一分钟游戏和异常场景验收。

首个契约版本必须明确时间基准、方向坐标、动作取消、音频格式边界、工具结果及文件归属。产品选择未确认时可准备样例与接口草案，不把推荐值写成已批准规则。真实平台尚未验证的字段和音频参数明确标为待验证。

## 3. 统一验收记录

每个计划书中的验收项使用唯一编号，记录至少包含：

| 字段 | 要求 |
| --- | --- |
| 用例编号 | 如 `M1-A03`，与计划对应 |
| 结果 | 未执行、通过、未通过、阻塞 |
| 环境 | 代码版本或工作区差异、浏览器/系统、设备、网络及必要配置 |
| 操作与输入 | 可重复的步骤、样例、本局编号、请求编号和测试时间 |
| 观察结果 | 实际状态、时间、分数、输出或错误；不能只写“正常” |
| 证据 | 自动检查输出、脱敏事件记录、截图、录屏或真机记录的真实路径 |
| 复核 | 执行者、复核者和实际验证日期 |

没有环境或凭证的必验项记为“阻塞”，不能记为通过。固定样例、协议模拟、真实灵矽和 iOS 真机结果分别记录。验收涉及的日志、协议状态和错误值使用英文，面向玩家的提示和记录说明使用中文；证据不包含密钥、设备凭证或原始私人对话。

测试和启动命令由 M0 在实际工程建立后登记，模块补充自身实际命令及退出结果。本轮没有可执行工程，不预先声称某条命令或测试已经运行通过。

## 4. 完成与交接条件

- 计划中的必验项全部通过；尚未通过或阻塞时，模块状态保持未完成。
- 约定的代码、模块说明和验证证据已经交付，并由验收负责人复核。
- 修改局限在模块负责范围；共享契约、根依赖或业务规则的变化已经获得对应评审。
- 模块测试通过后仍需完成相关联调，不能用模拟结果代替真实能力。
- 角色形象、主观听感和整体体验需要用户评审；自动检查不代替这些评审。
- 代码开发完成先自审，提交、合并和发布仍按用户明确授权执行。

当前所有计划的验收结果均为未执行。计划不承诺缺少依据的工期，也不预先填写测试成绩。
