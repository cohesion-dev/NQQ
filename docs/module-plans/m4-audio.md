# M4 执行计划：浏览器音频

本计划面向音频负责人，目标是可靠采集、传递和播放音频，并及时停止旧声音。状态为待评审、未实施；音频架构依据[实现方案](../implementation-plan.md)，验收记录见[统一要求](README.md)。

## 1. 范围、依赖与交付

- 负责 `web/src/audio/`、本地音效和配音资源、录音回放演示及本模块说明。
- 输入：M3 的录音意图、M5 协商并规范化的音频参数和帧、播放开始/结束/打断事件。
- 输出：采集音频帧、录音状态、播放状态、嘴型所需音量和资源释放结果。
- 不直接实现灵矽协议或开第二条网络连接。M5 负责必要的压缩音频解码；M4 与 M5 先共同验证边界格式，再由 M0 固定契约。

PCM（Pulse-Code Modulation，脉冲编码调制，未压缩音频）的采样率、声道、每样本位数、字节序和帧时长均写入契约；不得默认浏览器输入采样率就是上游要求的采样率。

## 2. 执行步骤与阶段产物

| 阶段 | 工作 | 交付物 | 验证项 |
| --- | --- | --- | --- |
| M4-1：格式与样本 | 与 M5 确定实际支持格式，准备已知采样率与时长的音频样本 | 参数表与样本说明 | 帧格式和时间关系可核对 |
| M4-2：采音 | 实现授权、开始/停止、重采样、分帧和尾帧处理 | 独立录音回放演示 | 无重复采集，停止后无残留麦克风 |
| M4-3：播放 | 顺序调度规范化音频、音量采样和本地音效 | 音频与嘴型输入演示 | 顺序正确，声音时长与样本一致 |
| M4-4：打断与释放 | 实现播放代次、清空缓冲、手势取消和前后台释放 | 取消与资源状态记录 | 新录音不继续播放旧声音 |
| M4-5：真实联调 | 与 M5 接通语音问答，再由 M6 检查网页容器 | 浏览器与真机音频记录 | 真实识别、实际回复和生命周期通过 |

## 3. 必验标准

| 编号 | 给定条件与操作 | 预期结果 | 验证方式 |
| --- | --- | --- | --- |
| M4-A01 | 首次点击录音，分别允许和拒绝麦克风 | 状态准确，拒绝可恢复；无未处理异常，不影响文字模式 | 授权操作记录 |
| M4-A02 | 连续开始/停止采集，检查帧参数及样本总量 | 声道、字节序、位数和帧尺寸符合契约；序号连续，尾帧按约定处理 | 帧元数据与字节断言 |
| M4-A03 | 以两种浏览器实际输入采样率处理已知频率、时长的样本 | 输出采样率正确，时长和音调不因直接改采样率标签而失真 | 合成样本与采样数检查 |
| M4-A04 | 播放有明确顺序和时长的多帧样本 | 无重复、倒序或异常重叠；输出总时长符合采样数及允许调度误差 | 样本播放与调度记录 |
| M4-A05 | 旧回复还有缓冲时再次按住录音，再补送旧播放代次的帧 | 当前调度周期内取消旧播放；作废帧不再入队，开始采集新语音 | 代次记录、录屏和听感检查 |
| M4-A06 | 正在采音时松手、手势取消、页面隐藏或结束本局 | 采集停止；尾帧或丢弃行为按契约完成，麦克风轨道关闭 | 状态、轨道与帧记录 |
| M4-A07 | 授权尚未返回时取消录音，随后系统才允许 | 不意外开始录音，已获得的设备轨道被释放 | 延迟授权演练 |
| M4-A08 | 同时收到聊天播放和本地喘气/入袋音效，随后用户开麦 | 符合共同确认的播放优先级；开麦结束当前台词，旧台词不排长队重播 | 事件顺序与听感记录 |
| M4-A09 | 播放、静音、打断和结束依次发生 | 音量回调对应实际播放，静音与结束归零，嘴型输入不残留 | 音量时间线 |
| M4-A10 | 连续三次建立并销毁音频模块 | 无遗留轨道、播放节点、监听器或不断增长的待播队列 | 资源状态对照 |
| M4-A11 | 与 M5 完成真实语音提问和回复，正常结束及再次开麦 | 用户语音被识别、回复可听；打断后旧音频不在新一轮恢复 | 脱敏事件记录与听感验收 |
| M4-A12 | 在目标 iPhone 浏览器及网页容器中完成录音、回复、锁屏和恢复 | 权限与设备状态正确，恢复后需按状态重新启动；不自动采音或重播旧回复 | 与 M6 的真机记录 |

M4-A03 使用 1 秒已知样本，建议验收为输出采样数相对约定采样率的误差不超过 1 个样本。M4-A04 的数字音频总时长须与有效采样数一致，调度偏差建议不超过一个约定音频帧时长。帧大小和尾帧补齐或有效样本标记由 M0/M4/M5 在格式评审中确定；这些是待评审目标，不是实测成绩。听感项另行记录可重复的断裂、噪声、音调错误和重叠。

## 4. 交付与阻塞处理

交付采集与播放代码、规范化帧说明、音效资源来源、本地演示、实际运行方式和验收证据。没有实际灵矽音频格式时可先做已知样本验证；M4-A11/A12 仍保持未完成，不用录音回放结果替代。

M4 负责页面采集和播放，M6 负责原生音频会话；相关恢复行为共同复核，避免两端重复启动麦克风或各自管理另一条播放链路。
