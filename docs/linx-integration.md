# 灵矽联调指南

本页说明当前开发版本如何接入灵矽。模型和输出声音按本轮授权使用占位实现；正式模型、导出素材和灵矽压缩音频解码不属于本次已完成功能。真实平台行为仍需用实际账号验证。

## 1. 控制台与本地配置

在灵矽控制台准备牛七七智能体，选择中文音色及支持工具调用的模型，启用统一意图识别并保存配置。角色提示建议：

```text
你是牛七七，一只蒙着眼睛听玩家导航抓苹果的小牛，说话简短俏皮。
玩家要求移动、转圈或停止时，调用相应设备工具，不要只口头答应。
左和右按玩家画面判断；向前靠近玩家，向后远离玩家。
只在工具返回完成后说明结果，取消或失败时不能声称已经做完。
得分、剩余时间和疲惫状态以工具结果为准，不猜测苹果位置，不自动寻路。
普通问题可以直接回答。需要实际状态时调用状态查询工具。
```

按 `.env.example` 创建本地 `.env`，填写：

| 字段 | 作用 |
| --- | --- |
| `LINX_AGENT_ID` | 牛七七智能体编号，真实模式必填 |
| `LINX_API_KEY` | 可选，服务端自动绑定激活设备所需访问密钥 |
| `LINX_DEVICE_ID` | 可选，复用已有绑定设备；不填则按浏览器会话建立虚拟设备 |
| `PORT` | 独立服务端口，默认 8787；开发页面由 Vite 决定端口 |

配置修改后重启开发服务。不要把密钥写入前端变量或提交到仓库。本地设备记录保存在被忽略的 `.linx-devices.json`，重启服务后可继续使用同一设备；删除它会丢失本地会话到设备的映射，但不会自动解绑平台设备。

## 2. 首次连接

1. `npm run dev`，打开页面。页面启动后自动建立连续语音通话；页面不提供电话按钮、本地模式切换、文字输入或动作按钮。
2. 网关分配独立浏览器会话，向设备网关请求激活信息。
3. 有密钥时自动绑定；没有密钥时页面显示激活码，在控制台手动绑定后点重试。
4. 服务端用设备凭证连接灵矽，发送能力声明并响应工具初始化、工具发现。
5. 完成握手和工具发现后即可聊天；聊天期间不启动游戏倒计时，只有 `start_apple_game` 工具成功后才开始本局。

真实设备激活、绑定接口依据[设备网关](https://linx.qiniu.com/docs/xrobot/platform/OTA)与[设备接口](https://linx.qiniu.com/docs/xrobot/api/device)。账号密钥权限和虚拟设备接受情况必须实测，错误不能用模拟成功替代。

## 3. 工具与输入输出

MCP（Model Context Protocol，模型上下文协议，用于发现和调用工具）消息封装在设备连接中。当前唯一工具定义位于 `shared/tools.ts`：

- `self.niuqiqi.start_apple_game`：玩家明确想玩抓苹果时切换游戏模式。
- `self.niuqiqi.do_action`：动作集合 `left/right/forward/backward/spin/somersault/dance/stop`；游戏移动步数为 1 到 3，触边后提前结束，移动动作包含转向、行走和回正阶段；聊天模式允许 `spin`、`somersault`、`dance` 和 `stop`，它们不启动游戏也不计分。聊天模式使用正视镜头，游戏模式使用斜上方抓苹果镜头。
- `self.niuqiqi.exit_apple_game`：玩家明确退出游戏时回到聊天模式。
- `self.niuqiqi.get_status`：读取本局阶段、分数、剩余毫秒和疲惫状态，不报告苹果坐标。

网关与页面共用 `canPerformAction` 的模式限制。聊天技能完成后才返回 `completed`；停止、切模式、断线或超时会返回 `cancelled`。聊天跳舞工具等待上限为 12 秒，覆盖最长约 8.17 秒的片段，其余工具保持 6 秒。苹果游戏中的动作仍由游戏引擎执行。相同请求编号的重复调用不重复执行；超时结果不会自动重放。

当前模型为 `niu_qi_qi.glb`，实际解析得到 34 个骨骼和 19 个动画片段，见[模型动作清单](model-assets.md)。聊天绕圈为半径约一米的圆周行走，共约 4.2 秒，脚步使用 `Walking`。跳舞随机选择四个候选之一，翻跟头使用 `Backflip`，两者以真实片段结束事件结算，不再叠加程序旋转。双方结束说话后空闲十秒自动表演，用户开口即停止自动表演；此行为不向网关发送伪造工具结果。

游戏移动正常播放 `Running`，疲惫播放 `Walking`，实际速度与计分沿用本地规则。左右转身与抵达回正分别选用对应 `Idle_Turn_Left` / `Idle_Turn_Right`，动画按规则阶段进度采样，避免重复旋转或被过早截断。

声音链路分为两部分：

- 输入：页面启动后，浏览器采音并转换为 PCM（Pulse-Code Modulation，脉冲编码调制）16kHz 单声道、16 位小端、20 毫秒一帧；VAD（Voice Activity Detection，语音活动检测）检测到语音后发送监听开始，连续静音约 700 毫秒后发送监听停止。页面不提供挂断按钮，通话连接随页面生命周期管理。
- 输出：读取实际 `tts.sentence_start` 的回复文字，由浏览器语音合成占位。上游二进制语音不播放，不宣称已完成真实音色或 Opus（音频编码格式）解码。

麦克风工作线程不会把声音回放进扬声器。电话按钮开启后保持麦克风会话，点击电话按钮再次挂断；页面显示连接中、通话中和不可用状态。离开页面或进入后台会挂断并关闭设备轨道；拒绝权限后提示玩家重新授权，不提供文字或动作按钮兜底。文字显示开关只影响字幕和对话记录，记录最多保留最近 100 条。

网关保留文字消息用于开发联调，玩家界面不暴露文字入口。文字按官方带文本的 `listen.detect` 示例提交；其普通聊天与工具触发行为仍需实际验证，不能以本地解析替代语音链路。[通信与音频协议](https://linx.qiniu.com/docs/xrobot/platform/websocket) · [端侧工具协议](https://linx.qiniu.com/docs/xrobot/mcp/hardware-mcp)

## 4. 联调顺序与成功证据

1. 按住说“你叫什么名字”，确认聊天模式的真实回复字幕和浏览器占位朗读。
2. 说“我想玩抓苹果”，确认真实开始游戏工具调用、规则展示、蒙眼和倒计时。
3. 按住说“向左走一步”，确认真实动作工具调用、位置变化及对应编号的完成结果。
4. 发停止动作，确认当前和等待请求取消，工具返回取消或停止结果。
5. 默认 1 分钟苹果寿命完成抓取并坚持到三分钟结算；记录识别、工具和动作延迟。
6. 两个独立浏览器会话分别连接，确认字幕、动作和得分不串台。若配置固定设备，只允许其中一个使用它。

只有账号和实际链路的证据齐全，才能把真实联调标记通过。当前仅写入接入代码，不自动购买额度、创建智能体或发布应用。

## 5. 常见提示

| 提示码 | 排查 |
| --- | --- |
| `LINX_NOT_CONFIGURED` | 填写智能体编号并重启开发服务 |
| 激活码 | 在控制台绑定到牛七七，保留浏览器会话后重试 |
| `DEVICE_BIND_FAILED` | 核对密钥权限、智能体编号和激活码状态 |
| `DEVICE_IN_USE` | 关闭占用同一个固定设备的另一页面 |
| `LINX_SETUP_TIMEOUT` | 检查网络、设备、模型工具能力和初始化响应 |
| `LINX_CONNECTION_FAILED` | 检查设备绑定、凭证和网络连接 |

网页要求真实连接才能开局；连接失败时显示原因并允许重试，不用模拟结果冒充真实语音验证。
