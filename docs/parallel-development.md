# 牛七七模块划分与并行协作方案

本文用于分配开发任务，说明模块边界、输入输出、可并行条件和验收要求。当前只整理协作方案，未启动执行者或开发业务代码。

玩法、技术方案和对外工具定义以[实现方案](implementation-plan.md)为准，本文不另维护一套游戏规则。形象、方向、自动抓取和疲惫表现沿用实现方案中的待评审选择，模块划分不表示这些选择已经确认。

M0～M6 的分阶段任务、交付物和逐项验收标准见[模块执行计划与验收入口](module-plans/README.md)。

## 1. 分工总览

推荐拆为六个开发模块，另设一项共享契约与集成职责。模块是代码职责边界，不要求每个模块都由不同的人负责，也不拆成六个独立运行的服务。

| 编号 | 模块或职责 | 独占修改范围（拟议） | 核心交付 | 能否先独立推进 |
| --- | --- | --- | --- | --- |
| M0 | 共享契约与应用集成 | `shared/`、根配置和锁文件、`web/src/main.ts`、端到端联调资料 | 共享类型、工作区基础、依赖锁定、模块装配和完整链路 | 先完成最小契约，随后持续集成 |
| M1 | 游戏逻辑 | `web/src/game/` 及其规则测试 | 一分钟规则、两个苹果槽、动作、碰撞、得分、疲惫状态 | 契约确认后可独立开发，不依赖灵矽 |
| M2 | 三维角色与场景 | `web/src/scene/`、角色和场景资源 | 牛、眼罩、口袋、场地、苹果、动作与入袋效果 | 可用固定状态和事件开发 |
| M3 | 页面与交互 | `web/src/ui/`、页面样式、界面资源 | 准备页、计时计分、聊天、控制按钮和结算页 | 可用固定状态和连接事件开发 |
| M4 | 浏览器音频 | `web/src/audio/`、本地配音及音效资源 | 采音、分帧、重采样、播放、打断和资源释放 | 可先用录音回放验证，真实格式需与 M5 联调 |
| M5 | 灵矽接入与会话 | `server/`、`web/src/linx/`、接入说明 | 设备身份与绑定、网关、页面连接适配、工具路由和音频解码 | 可先用最小工具执行器验证真实灵矽链路 |
| M6 | iOS 外壳 | `ios/`、原生运行说明 | 网页容器、麦克风权限、音频会话、前后台处理 | 外壳可先搭建，最终依赖移动网页和加密站点 |

M0 是集成职责，可由 M1 或另一位负责人兼任，不必额外安排专职人员。M5 同时负责网关和页面连接适配，让同一人掌握连接两端，减少消息协议分叉。

每个模块负责人维护自己范围内的测试与开发说明。上表中的代码目录目前尚未创建，只是后续开发时的归属约定。

## 2. 并行前先确定的共享契约

不能仅靠各自理解原方案就直接并行。先由 M0 汇总最小契约，各模块负责人共同评审，再开始独立实现。只定义当前游戏需要的类型和接口，不提前开发通用框架。

### 2.1 共享数据

| 契约 | 必须明确的内容 | 主要使用方 |
| --- | --- | --- |
| 本局信息 | 本局编号、开始与截止时间、苹果寿命、连接代次 | M1、M3、M5、M0 |
| 游戏快照 | 游戏阶段、牛的位置和姿态状态、当前苹果、分数、疲惫状态、剩余时间 | M1 产生，M2/M3 读取 |
| 游戏事件 | 苹果生成/抓取/过期、动作开始/完成/取消、疲惫变化、本局结束 | M1 产生，M2/M3/M4 消费 |
| 动作请求与结果 | 请求编号、本局编号、连接代次、动作与步数；实际执行结果及失败原因 | M5/M3 提交，M1 执行 |
| 连接与聊天事件 | 就绪、错误、恢复、识别文字、回复文字、工具调用与结果 | M5 产生或转发，M3/M0 使用 |
| 音频帧与播放事件 | 采样率、声道、采样格式、帧顺序、播放代次、开始/结束/打断 | M4、M5 |

数据结构只在 `shared/` 维护一份，网页与网关共同引用。字段名、单位、必填条件、允许值、错误语义和取消行为必须写清楚；开发者不在自己的目录里复制另一份。

时间统一用毫秒，位置统一用场景单位。M5 提供服务端开始与截止时间以及校时依据，M0 建立统一的当前时间读取入口，M1 接收该时间驱动规则，M2/M3 读取快照。三维渲染可以有表现用的动画时间，但不能据此延长游戏或决定得分。

游戏坐标和镜头方向由 M0、M1、M2 一起确定，再写进共享约定。M2 不单独翻转坐标，M5 不自行解释另一套“向前”。

### 2.2 最小调用边界

| 调用边界 | 职责约定 |
| --- | --- |
| M0 → M1 | 创建本局、推进时间、提交或取消动作、读取快照和事件、结束本局 |
| M0 → M2 | 传入快照和有序事件，驱动渲染、调整尺寸、释放场景 |
| M0 → M3 | 显示游戏和连接状态；接收开始、方向、停止、文字和录音手势 |
| M0 → M4 | 开始/停止采音，收发音频帧，播放本地音效，取消播放并释放设备 |
| M0 → M5 | 建立连接、请求开始本局、发送文字或语音、接收工具请求、提交结果、关闭连接 |
| M6 → 网页 | 通知进入后台或恢复前台；原生端不直接操作苹果和分数 |

上述是拟议接口职责，具体方法名称和参数由共享契约评审确定。`web/src/main.ts` 只装配模块和转发事件，不承载苹果规则、音频编解码或灵矽协议实现。

M1 的动作结果在逻辑执行完成后产生，不能等待 M2 的入袋或嘴型动画才能完成工具响应。M2 负责把结果演出来，不反向决定是否抓到。

### 2.3 固定测试数据

M0 提供共享的最小样例：准备状态、正常运行、抓到一颗苹果、苹果过期、疲惫和结算，以及一次动作调用与结果、一轮音频开始/结束事件。

M2/M3 可以据此开发，M5 可以连接一个遵循契约的最小执行器。模拟数据只用于模块开发，不算真实灵矽或 iOS 验收通过。视觉评审使用的苹果和角色坐标必须符合共享坐标约定。

## 3. 各模块任务与验收

### M1：游戏逻辑

**任务**：实现本局状态、单一规则时钟、两个苹果补位槽、移动与边界、路径碰撞、抓取计分、动作队列、优先停止、疲惫计数和截止结算。

**边界**：不依赖三维渲染库、网页元素、麦克风或灵矽连接；随机位置生成可注入固定随机序列，时间由外部传入，便于确定性测试。所有得分和苹果状态只从这里改变。

**独立验收**：

- 开局两颗，每个苹果独立到期；抓到或到期后恰好等待 1 秒补位。
- 苹果重复碰撞、抓取和过期竞争时只计分或补位一次。
- 苹果过期不扣分、不结束本局；第 60 秒停止抓取和补位。
- 停止取消当前与排队动作；重复请求、旧局请求不重复移动。
- 卡顿或恢复前台后按截止时间更新，不补记错过的得分。

### M2：三维角色与场景

**任务**：实现蒙眼牛、口袋、场地、苹果和光照；实现待机、走路、转圈、伸手、苹果入袋、过期消失、扶腿喘气、恢复及简单嘴部开合。

**边界**：仅读快照和事件，不写分数，不另开苹果寿命定时器，不因动画结束去生成苹果。动画暂未完成时也必须准确呈现牛的逻辑位置。

**独立验收**：固定样例下能演示所有动作；疲惫和移动可组合，身体不明显穿插；苹果正确进入口袋；手机尺寸下场地和角色不被裁切。最终性能以目标真机实测为准。

### M3：页面与交互

**任务**：实现准备、进行、结算三个页面状态，苹果寿命输入、倒计时、分数、字幕、文字输入、方向与停止按钮、按住说话手势，以及权限与连接提示。

**边界**：提交玩家意图，不直接改牛位置；显示快照中的时间和分数，不独立计算另一份。录音手势交给 M4，连接请求交给 M5，通过 M0 装配。

**独立验收**：可用固定数据切换三个状态；苹果寿命拒绝非法数值；拒绝麦克风后文字和按钮仍可用；按住说话在松手、手势取消或页面隐藏时均停止；手机软键盘不遮挡输入与发送。

### M4：浏览器音频

**任务**：采集麦克风音频、分帧与重采样、顺序播放远程音频和本地音效、提供嘴型所需播放音量、取消旧播放、释放音频设备。

**边界**：不发明灵矽消息，不自行建立第二条连接。通过共享音频契约与 M5 交换帧；原生压缩音频解码若需要，由 M5 负责统一完成，页面消费约定的未压缩音频。

**独立验收**：在授权后录音并回放；分帧格式正确；再次开麦停止旧播报并清空缓冲；旧播放代次的数据不再发声；停止或后台后麦克风释放；本地音效与聊天不无序重叠。

### M5：灵矽接入与会话

**任务**：虚拟设备身份、激活绑定、凭证、灵矽连接、工具初始化与发现、文字和语音接入、实际音频格式与解码、网页消息适配、超时与去重、本局截止和连接清理。

**边界**：MCP（Model Context Protocol，模型上下文协议，用于发现和调用工具）适配在这里完成，游戏动作由 M1 执行。网关不自动寻路、不更改前端分数；管理凭证留在服务端。

**独立验收**：

- 使用最小执行器接到一次真实动作调用，执行一次并返回匹配编号的结果。
- 普通语音和文字问题均完成真实问答，确认文字入口而非仅显示字幕。
- 确认实际音频编码、参数和解码输出，与 M4 的约定一致。
- 两个页面会话互不串台；工具执行结果超时或取消后不自动重放。
- 开始本局时返回统一截止时间，截止后拒绝旧动作并清理上游连接。

设备身份、密钥权限、文字入口和音频编码均属于原方案列出的待实测事项。先做真实接入验证并把证据反馈其他模块；若契约要变，先同步变更，不让其他人继续依赖错误假设。

### M6：iOS 外壳

**任务**：搭建 WKWebView（iOS 系统网页容器），加载同一套页面；处理麦克风用途与权限、音频会话、安全区域、后台与前台通知及调试说明。

**边界**：不复制游戏规则、不直接连接另一套灵矽服务、不在原生包中保存管理密钥。

**独立验收**：可先加载简单测试页验证权限和生命周期；最终连接实际游戏站点完成语音抓苹果和一分钟结算。锁屏或后台不延长本局，返回时不重放旧动作。可安装包的签名与发布按后续实际授权处理。

## 4. 如何安排并行顺序

| 阶段 | 可以同时进行的工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：契约准备 | M0 汇总契约，各模块负责人评审；M5 核对真实接入前提 | 类型、单位、坐标、消息归属、取消行为和文件归属确定 |
| B：模块并行 | M1 写纯规则；M2 演示角色；M3 做界面；M4 做录音回放；M5 联调灵矽；M6 验证外壳 | 各自独立验收通过，暴露真实依赖与限制 |
| C：两路集成 | M1＋M2＋M3 合成本地游戏；M4＋M5 合成真实语音与工具链路；M6 跟进移动端兼容 | 本地能玩完整一分钟，真实灵矽能调用并收到实际结果 |
| D：完整联调 | M0 接合两路，所有负责人处理自身边界内的问题 | 语音和文字驱动真实游戏，停止、过期、疲惫、结算和后台行为一致 |

阶段 B 可以并行，但 M5 的接入问题必须尽早暴露。没有实际账号时其他模块仍能工作，不能因此把接入模块标记为完成。

本地按钮操作用于验证游戏规则，真实语音验收另行记录说话结束到动作开始的延迟，尤其核查默认 3 秒苹果寿命下的实际可玩性。

## 5. 按人数分配

### 两人

| 执行者 | 主责 | 并行工作 |
| --- | --- | --- |
| A：游戏与页面 | M0、M1、M2、M3 | 先固定契约，再完成本地游戏；维护根配置和应用装配 |
| B：灵矽与音频 | M4、M5；后续承担 M6 | 独立跑通音频和真实工具调用；共享网页可运行后做 iOS 外壳 |

两人先共同确认契约，随后 A 不等待账号联调，B 不等待完整牛模型。集成时 A 装配页面，B 提供连接、音频和工具适配，不同时修改应用入口。

### 四人（推荐）

| 执行者 | 主责 |
| --- | --- |
| A：游戏逻辑与集成 | M0、M1 |
| B：视觉与交互 | M2、M3 |
| C：音频与移动端 | M4、M6 |
| D：灵矽接入 | M5 |

该分工分别覆盖规则、视觉、音频和平台接入，职责关联紧密，交叉修改少。M6 可在 M4 的基本链路明确后推进，不阻塞浏览器版本。

### 更多人员

可将 M2 与 M3、M4 与 M6 分给不同负责人，M0 仍指定唯一集成人。人数增加后按模块拆分测试和说明文档，不新增一套业务协议或扩大游戏功能。

## 6. 避免冲突的工作约定

1. 每个模块使用独立分支和工作目录，先声明自己负责的目录；共享契约和根依赖由 M0 统一修改。
2. 根依赖配置、锁文件、构建配置和 `web/src/main.ts` 只由集成负责人维护。其他负责人提交依赖及装配需求，由 M0 加入，避免锁文件反复冲突。
3. 新增共享字段前，说明修改原因、旧新数据样例、受影响模块和兼容方式，由使用方确认后再更新唯一契约。实际解码格式未知时，先验证再固定，不能让两端各自猜测。
4. 不跨目录重构别人的模块；发现问题先反馈负责人。确需跨模块改动时，先明确新的文件归属或共同评审。
5. 每个模块交付时提供修改范围、输入输出、运行或演示方式、验证结果和未完成项；真实联调与模拟验证分别说明。
6. 集成负责人审阅各模块改动、共享契约和完整场景，不以各自模块测试通过代替联调通过。
7. 提交、合并和发布仍遵循用户授权；本协作方案本身不授权启动开发或自动提交。

## 7. 整体完成标准

- 角色在手机页面中可见、蒙眼、可按指令移动，抓取表现为苹果进入口袋。
- 已确认的苹果、补位、得分和固定一分钟规则全部通过规则测试及完整试玩。
- 按钮、文字和灵矽语音调用同一动作执行入口，模型得到实际结果。
- 疲惫和聊天并行；新开麦或停止动作能正确取消对应任务。
- 两个用户独立运行；旧连接和上一局请求不能影响当前局。
- iPhone 上验证麦克风、播放、锁屏、后台和一分钟结算；未做真机验证时明确保留未完成状态。
- 默认 3 秒寿命下记录实际交互延迟和试玩结果，保持默认规则，调整需用户确认。

完成这些检查后，再由用户评审整体结果。
